# AGENTS.md — SCM (Science Content Machine)

Этот файл читается агентом в каждой сессии. Он фиксирует парадигму проекта,
роли и правила, чтобы не расползаться по чужим проектам.

## Парадигма

**SCM = Scientific Content Machine** — детерминированная машина научного
контента: источники → проверяемое знание → публикация → сайт → метрики →
коммерческая ветка.

SCM — одна из веток экосистемы. Внешние системы (`RII`, `AI Connector`,
`KERN`, `NYUUI`, `Эмбрион-Симбиот`) — **оракулы и поставщики знаний**, а не
части этого репозитория. Их код здесь не меняется.

## Роли

| Роль | Кто | Права |
|:--|:--|:--|
| Главный оператор | владелец | решения, публикация, подпись фактов, секреты |
| ИИ-инструмент | агент | анализ, код, тесты, документация, предложения |
| Оракулы | RII / KERN / Z3 / Lean / PTE | ставят `PROVEN`, а не агент |

Правило: **текст агента — не доказательство**. `PROVEN` ставит оракул или
владелец. Заметка агента остаётся `UNPROVEN` до подписи.

## Границы

1. Работаем **только в SCM**. Не правим `RII`, `kern`, `nyuui-core`,
   `АССИСТЕНТ` и другие проекты без отдельного задания.
2. Внешние вызовы — только через документированные интерфейсы (MCP/HTTP/CLI)
   и только read-only, если владелец не разрешил запись.
3. Секреты не печатаем, не коммитим, не кладём в открытые базы.
4. Контент без LLM: генерация текста моделью не является источником.
5. Любое изменение — с тестом и прогоном ворот.

## Документация

Документация — часть продукта. Правила:

- `docs/INDEX.md` — карта документов;
- `docs/SCM.md` — парадигма и архитектура;
- `docs/OPERATOR.md` — вход оператора и ежедневные действия;
- `docs/ECOSYSTEM.md` — место SCM в экосистеме;
- `docs/KNOWLEDGE_BASE.md` — база знаний и provenance;
- `docs/LITERATURE.md` — литература SCM;
- `docs/RUNBOOKS.md` — запуск, публикация, backup, recover;
- `docs/SECURITY.md` — секреты и инциденты;
- `docs/DECISIONS.md` — принятые решения;
- `docs/GLOSSARY.md` — термины.

При изменении поведения обновляй соответствующий документ **тем же коммитом**.
Числа (тесты, посты, метрики) берутся из команд, а не из памяти.

## Порядок работы

1. Прочитать `docs/INDEX.md` и нужный документ.
2. Сформулировать проверяемое свойство.
3. Сделать минимальное изменение + тест.
4. Прогнать:

```bash
python -m unittest discover
python -m science_pulse.cli verify
python -m science_pulse.cli preflight --no-media
python -m science_pulse.cli knowledge integrity
```

5. Обновить документацию и `CHRONICLE`/`docs/DECISIONS.md`.
6. Коммит: что сломано → что сделано → как проверено.

## Запрещено

| Нельзя | Почему |
|:--|:--|
| `except: pass` | сбой становится невидимым |
| «Починить» без прогона тестов | агент выглядит работающим, система — нет |
| Дублировать функцию вместо переиспользования | расхождение поведения |
| Менять чужие проекты | нарушение границ экосистемы |
| Коммитить `.env`, токены, ключи | утечка |
| Объявлять `PROVEN` без оракула/подписи | подмена истины |
