# Граф знаний: PageRank и диск Пуанкаре

Документ описывает расчёт графа знаний Science Pulse: как посты связываются,
как считается PageRank, как узлы раскладываются в диск Пуанкаре и как это
используется в сайте и на edge (Cloudflare).

Код: `science_pulse/graph.py` (чистые функции, без сети и LLM).
Тесты: `tests/test_graph.py`, `tests/test_site.py`.

## Зачем

Каждый пост — узел. Узлы связаны по общим научным понятиям (ключевые слова).
PageRank показывает «центральность» темы, диск Пуанкаре даёт стабильную
раскладку: важное — в центре, редкое — по краям. Это делает сайт похожим на
растущую карту знаний, а не на ленту.

## 1. Рёбра: `build_links(posts, min_weight=2, max_links=400)`

1. Для каждого поста берётся множество ключевых слов
   `keywords(title + " " + body, 10)`.
2. Для каждой пары постов считается пересечение множеств — это **вес ребра**.
3. Ребро добавляется, если вес ≥ `min_weight` (по умолчанию 2).
4. Рёбра сортируются по весу убыв., затем по `source`/`target` (детерминизм),
   и обрезаются до `max_links`.

Граф **неориентированный**: связь симметрична.

## 2. PageRank: `pagerank(node_ids, links, damping=0.85, iterations=40)`

Взвешенный PageRank чистым Python (без numpy). Формула на каждой итерации:

```
rank[v] = (1 − d)/N  +  d · dangling/N  +  d · Σ_{u→v} rank[u] · w(u,v) / W(u)
```

где `W(u)` — сумма весов рёбер узла `u`, `dangling` — суммарный ранг узлов без
рёбер (висячих), `N` — число узлов, `d = 0.85`.

Особенности реализации:

- **Висячие узлы** распределяют свою массу равномерно по всем узлам — сумма
  рангов сохраняется.
- После каждой итерации ранги **нормируются** (сумма = 1).
- Результат **детерминирован**: одинаковый вход → одинаковый выход (тест
  `test_pagerank_deterministic`).
- Сложность: `O(iterations · E)`, где `E` — число рёбер. Для сотен постов —
  миллисекунды.

## 3. Раскладка: `poincare_layout(node_ids, domains, rank)`

- Узлы сортируются по PageRank убыв. (при равенстве — по id).
- Координаты берутся из `SOTAKVExtensions.poincare_xy(index, total, domain)`:
  - важнейший узел (index 0) — в центре диска;
  - дисциплина задаёт сектор (`math` / `physics` / `cs`);
  - радиус растёт к границе единичного диска.
- Все точки лежат строго внутри единичного диска `x² + y² < 1`.

## 4. Топ: `top_by_pagerank(node_ids, rank, limit=5)`

Возвращает `limit` самых «центральных» узлов — для блока «Топ по PageRank»
на главной странице.

## 5. Контракт `graph.json`

```json
{
  "nodes": [
    {"id": "…", "title": "…", "domain": "math",
     "value": 4, "pagerank": 0.333333333, "x": -0.0365, "y": -0.1648}
  ],
  "links": [
    {"source": "…", "target": "…", "weight": 3}
  ]
}
```

Поля узла: `value` — приблизительный размер (длина тела), `pagerank` —
нормированный ранг, `x`/`y` — координаты в единичном диске.

## 6. Как это показывается

**Сайт (`science_pulse/site.py`)**

- `_graph_data(posts)` считает узлы/рёбра/ранги/раскладку один раз и
  переиспользуется в `_write_graph` и в `_write_index`.
- На главной — блок «Граф знаний» и «Топ по PageRank» (ранг в ‰).
- Отрисовка: `vis-network` с `physics: false`; позиции узлов заданы `x/y`
  (умножены на `SCALE = 320`), размер ∝ `√pagerank`, цвет — по дисциплине.

**Edge (Cloudflare, `cloudflare/worker.js`)**

- `GET /api/graph` отдаёт узлы из D1 с полями `pagerank`, `poincare_x`,
  `poincare_y` — тот же контракт, что и локальный `graph.json`.

## 7. Проверка

```bash
python -m unittest tests.test_graph -v
python -m science_pulse.cli site
python -c "import json;d=json.load(open('dist/graph.json'));print(len(d['nodes']),'узлов',len(d['links']),'рёбер')"
```

Критерии: сумма `pagerank` = 1, все точки внутри диска, повторная сборка даёт
тот же результат.
