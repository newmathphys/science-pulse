# SCM — Scientific Content Machine

**SCM** — детерминированная машина научного контента. Она превращает открытые
научные источники в проверяемые публикации, сайт, метрики и коммерческую
ветку. SCM не «пишет науку моделью»: она собирает, проверяет, оформляет и
публикует то, у чего есть источник.

## 1. Формула

```text
SCM = Источники
    → Проверяемое знание
    → Публикация (Telegram / Threads / сайт)
    → Обратная связь (метрики)
    → Коммерческая ветка
```

## 2. Четыре ветки одной системы

| Ветка | Что производит | Критерий качества |
|:--|:--|:--|
| **Научная** | формулы, факты, задачи, доказательства | источник + статус (`PROVEN`/`EMPIRIC`/`HYPOTHESIS`) |
| **Публицистическая** | посты, карточки, фильмы, голос, сайт | понятность, точность, отсутствие «воды» |
| **Коммерческая** | аудитория, продукты, подписка, книга, консультации | измеримая конверсия, а не обещания |
| **Языковая** | регистры: наука / лекция / пост / оффер | один смысл — разные регистры, без подмены факта |

## 3. Три контура

1. **Добыча** — источники, качество, дедупликация, очередь.
2. **Производство** — текст, формулы, карточка, фильм, звук.
3. **Публикация** — площадки, идемпотентность, метрики, обратная связь.

## 4. Три эшелона устойчивости

1. Онлайн-источники (Wikipedia, Stack Exchange, OEIS, arXiv, Rosetta, GitHub).
2. Очередь в SQLite — публикация не зависит от источника в момент выхода.
3. Офлайн-бункер SymPy + CODATA — работает без сети.

## 5. Роли и истина

```text
владелец = главный оператор
агент    = ИИ-инструмент
оракул   = RII / KERN / Z3 / Lean / PTE
```

- владелец принимает решения и подписывает факты;
- агент предлагает, пишет код, тесты и документацию;
- `PROVEN` ставит оракул, не агент;
- заметка агента — `UNPROVEN` до подписи.

### 5.1. Запрет LLM в контенте

Контент собирается из источников и шаблонов, а не генерируется моделью.
Это проверяется, а не декларируется:

- `science_pulse/no_llm.py` сканирует AST всех модулей пакета;
- запрещены импорты `openai`, `anthropic`, `ollama`, `transformers`,
  `langchain`, `litellm` и подобных;
- запрещены адреса `api.openai.com`, `api.anthropic.com`,
  `generativelanguage.googleapis.com` и вызовы `chat.completions.create`;
- `translate` включён (`true`) для англоязычных источников; это бесплатный
  машинный перевод, не LLM. Гейт `no_llm` проверяет отсутствие LLM-импортов
  и генеративных API.

Поэтому `./sp check` каждый раз доказывает: в контентном контуре LLM нет.

## 6. Границы

SCM — **ветка экосистемы**, а не замена RII, KERN, NYUUI или Эмбриона.

| Система | Как используется |
|:--|:--|
| RII | оракул фактов и решений (`rii_probe_fact`, `rii_circuit_ask`) |
| AI Connector | черновики/перевод, но не источник истины |
| KERN | проверка кода и инвариантов (`e=1`) |
| NYUUI | корпус знаний и поиск (`campus_search`, `campus_truth`) |
| Эмбрион | операторский голосовой вход, read-only |

Код этих систем в SCM не изменяется.

## 7. Инварианты SCM

1. **Нет источника — нет публикации.**
2. **Нет подписи/оракула — нет `PROVEN`.**
3. **Повторная публикация не создаёт дубликат.**
4. **Карточка/фильм отражают данные поста, а не декор.**
5. **Секреты не попадают в Git, docs и открытые базы.**
6. **Документация обновляется тем же коммитом, что и поведение.**
7. **Числа в документации — измеренные, а не выдуманные.**

## 8. Что считается результатом

- пост в канале с источником, формулой и проверяемым следствием;
- запись в SQLite (`posts`, `publications`, `metrics`);
- карточка/фильм 1080×1080 или 9:16;
- страница сайта;
- запись в Knowledge Base (`documents`, `claims`, `notes`);
- метрика/отчёт, а не «ощущение, что работает».
