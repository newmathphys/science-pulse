# Решения SCM (ADR)

## D-001. SCM = Scientific Content Machine

**Решение:** проект развивается как детерминированная машина научного
контента, а не как «ещё один генератор текста LLM».

**Причина:** нужен проверяемый источник, повторяемость и коммерческая ветка
без подмены истины.

## D-002. Контент без LLM

**Решение:** текст берётся из источников; LLM не является источником факта.
Модель допустима как черновик/перевод, но результат проходит quality gate.

## D-003. Оракул ставит `PROVEN`

**Решение:** `PROVEN` ставит RII/KERN/Z3/Lean/PTE или владелец. Агент оставляет
`UNPROVEN`.

## D-004. Отдельная Knowledge Base SCM

**Решение:** `data/knowledge.db` хранит документы SCM, утверждения, заметки,
решения и метрики. Корпус NYUUI не дублируется.

## D-005. Book-фильм отдельным модулем

**Решение:** `book_film.py` — светлый книжный видео-движок; `moku_film.py` —
тёмный 3D. Оба доступны в `/ab`.

## D-006. Эталон голоса — Светлана

**Решение:** `ru-RU-SvetlanaNeural`; Google TTS-подмена выключена по умолчанию.
При сбое edge-tts допускается честная сонификация, но не подмена голоса.

## D-007. Пост ≠ радио

**Решение:** пост завершается «Разбор завершён», радио — «Эфир продолжается».
Это разные регистры.

## D-008. Документация тем же коммитом

**Решение:** изменение поведения без обновления docs не принимается.

## D-009. Только SCM

**Решение:** агент не меняет RII/KERN/NYUUI/АССИСТЕНТ и другие проекты без
отдельного задания. Внешние системы — оракулы и источники, не части репозитория.
