# A/B стилей карточки

Документ описывает встроенный механизм A/B-тестирования стиля карточки:
как выбирается вариант, где он хранится и как читать результаты через метрики.

Код: `science_pulse/abtest.py`, `science_pulse/cards.py` (`render_card`),
`science_pulse/pipeline.py`, `science_pulse/storage.py` (`metrics_by_style`).
Тесты: `tests/test_abtest.py`, `tests/test_storage.py`, `tests/test_metrics.py`.

## Идея

Каждый пост получает **детерминированный** вариант вёрстки. Вариант
записывается в `meta` поста, а затем сопоставляется с метриками площадок —
так видно, какой стиль собирает больше просмотров и реакций.

Генерация контента не меняется: это только вёрстка карточки.

## Варианты

| Вариант | Заголовок | Крючок | Назначение |
|:--|:--|:--|:--|
| `classic` | до 3 строк, 100% | показывается | текущий вид (по умолчанию) |
| `compact` | до 2 строк, 90% | скрыт | плотная карточка под короткие посты |

Список и параметры — в `abtest.STYLES`. Порядок `VARIANTS` фиксирован: он
влияет на выбор.

## Выбор варианта

`choose_variant(post_id)` берёт `sha1(post_id)` и берёт остаток по числу
вариантов. Поэтому:

- один и тот же пост всегда получает один и тот же стиль;
- при двух вариантах распределение примерно 50/50;
- пересборка сайта/карточки не «перекидывает» вариант.

## Включение

`config.yaml`:

```yaml
abtest:
  enabled: false          # включите, когда есть токены площадок и метрики
  variants: ["classic", "compact"]
```

`enabled: false` (по умолчанию) → вариант не выбирается, карточка рендерится
как раньше (`variant=None` → стиль `classic`). Это сохраняет прежнее поведение
и не ломает существующие тесты.

## Что происходит при публикации

1. Если `abtest.enabled`, `pipeline.publish_next` вызывает `choose_variant`.
2. Вариант пишется в `post.meta["style_variant"]` и в БД
   (`storage.set_post_meta`, поле `meta_json`).
3. `render_card(..., variant=…)` применяет параметры стиля.
4. Ошибка записи варианта не блокирует публикацию (только warning).

## Как читать результаты

Сначала соберите метрики площадок:

```bash
python -m science_pulse.cli metrics --collect
python -m science_pulse.cli metrics
```

`storage.metrics_summary()["by_style"]` (и отчёт `format_metrics_summary`)
показывает агрегат по вариантам, если вариантов ≥ 2:

```
A/B стилей карточки:
  classic: 👁 1200 · ❤ 34 (постов 12)
  compact: 👁 1540 · ❤ 41 (постов 11)
```

В пульте — команда `/metrics`.

## Ограничения

- A/B осмыслен только при живых токенах и накопленных метриках; без них
  `by_style` пуст, а вариант влияет лишь на вёрстку.
- Метрики площадок асимметричны (Telegram/Discord не отдают просмотры),
  поэтому сравнивайте по площадкам, где статистика есть.
- Малая выборка даёт шум — накапливайте хотя бы десятки постов на вариант.
- Реализовано два варианта вёрстки; расширение — добавьте стиль в
  `abtest.STYLES` и имя в `VARIANTS`/`config.yaml`.
