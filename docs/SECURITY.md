# Безопасность SCM

## 1. Главное правило

Секреты живут **только** в:

- `.env` (локально, не коммитится);
- GitHub Secrets;
- Cloudflare Secrets;
- системном vault (`pass`/KWallet), если владелец так решил.

В `docs/`, `data/`, Git, чат и Knowledge Base секретов быть не должно.

## 2. Что нельзя делать

| Нельзя | Почему |
|:--|:--|
| печатать токен в ответ/лог | утечка в историю |
| коммитить `.env` | утечка в Git |
| класть ключи в `docs/`/`data/` | открытые базы |
| отдавать ссылку Telegram с `bot<TOKEN>` | токен виден в URL |
| публиковать Chrome-экспорт с паролями | компрометация аккаунтов |

## 3. Найденные риски вне SCM

При инвентаризации ПК обнаружены:

1. файл со строкой вида `nvapi-...` в открытом текстовом файле;
2. Chrome-экспорт с паролями/аккаунтами.

Значения в SCM **не копируются и не печатаются**. Действия владельца:

- перенести ключ в vault;
- отозвать/ротировать ключ;
- удалить/зашифровать экспорт;
- проверить, не попал ли ключ в Git-историю.

## 4. Токены площадок

| Токен | Где хранится | Ротация |
|:--|:--|:--|
| `TG_BOT_TOKEN` | `.env`/GitHub Secrets | при утечке |
| `TH_ACCESS_TOKEN` | `.env`/Secrets | 60 дней, refresh |
| `BLUESKY_APP_PASSWORD` | `.env`/Secrets | при утечке |
| `DISCORD_WEBHOOK_URL` | `.env`/Secrets | пересоздать webhook |
| `MASTODON_ACCESS_TOKEN` | `.env`/Secrets | при утечке |
| `VK_ACCESS_TOKEN` | `.env`/Secrets | при утечке |
| `CF_WORKER_URL` + `INGEST_SECRET` | Secrets | при утечке |

## 5. Инцидент

1. Остановить публикацию: `/pause` или `./sp stop`.
2. Отозвать токен у площадки.
3. Проверить `publications`/логи на несанкционированные посты.
4. Записать инцидент в `docs/DECISIONS.md`/CHRONICLE.
5. Ротировать секрет, обновить `.env`/Secrets.
6. Прогнать `./sp check`.

## 6. Проверка перед коммитом

```bash
git status
git diff --cached
grep -RInE "nvapi-|ghp_|AAG|bot[0-9]+:" --exclude-dir=.git .
```

Если секрет найден — **не коммитить**, сначала удалить/ротировать.
